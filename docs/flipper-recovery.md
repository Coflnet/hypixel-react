# Flipper feed recovery

The September 2026 reports of an empty or stalled `/flipper` feed exposed several client-side failure paths. The individual reports did not include connection traces, so these findings do not establish which path each reporter encountered.

- Anonymous filter edits cleared the cards without updating the server subscription. Saved checkbox values could also appear unchecked after hydration. Account filter updates did not refresh the settings provider, and updates with unchanged restriction lists emitted no change event. Controls and subscriptions now follow the current settings.
- Subscription callbacks retained old sold filters, and a callback-local duplicate lookup could hide a flip after clearing the list. Callbacks now read the current filter and clear duplicate tracking with the cards, preserving both card and summary counts. Sold notifications update React state immutably.
- Anonymous subscriptions removed the authenticated subscription type instead of replacing previous anonymous subscriptions. Delayed subscriptions and local subscription records survived page cleanup. Both flip subscription types are now replaced/cancelled together, including subscriptions waiting for a connection. A queued unsubscribe cannot cancel a newer feed after navigation.
- Reconnection waited indefinitely for connection setup or login replies, and a socket reporting OPEN had no inactivity check. Setup now has a 15-second deadline; 90 seconds without a server message triggers reconnection, checked every five seconds with the existing reconnect jitter. Reauthentication finishes before subscriptions and ordinary requests resume. Retired sockets cannot complete setup on a newer connection.
- The minimum-profit debounce was recreated on render and captured previous filter values. Its timer now survives renders, is cancelled on unmount, and merges with the current saved filters.

The sibling `SkyCommands/Socket/SkyblockBackEnd.cs` sends `nextUpdate` about every 59 seconds and `ping` 30 seconds later. Any incoming message counts as activity, including heartbeats with no matching subscription. Recovery does not depend on receiving a profitable flip, so quiet markets and restrictive filters do not cause reconnection loops. Browser timer suspension can delay recovery until the tab resumes.

`cypress/e2e/flipper-recovery.cy.ts` uses a simulated socket to cover filter changes, account settings, sold filters, clearing cards, silent sockets, healthy heartbeats, missing setup/login replies, authenticated restoration, and navigation while disconnected. These tests complement production-build and shared-connection regression checks. They do not diagnose a backend that continues sending heartbeats while its upstream flip producer is stalled.

Validated on 2026-09-19 with the production build and `tsc --noEmit`. Against `npm start` with both test-runner flags enabled, `npm run cypress:verify -- --spec cypress/e2e/flipper-recovery.cy.ts --config baseUrl=http://localhost:3107` passed all 13 cases in three consecutive processes (39 passes, no retries). The full Cypress suite also passed all 113 tests across 19 specs with retries disabled.
